## What it is

z3 is a satisfiability-modulo-theories solver. You declare variables (usually `BitVec`, which models fixed-width machine integers exactly, including wraparound), add constraints, and ask for a model. In CTF it solves crackmes, keygens, VM-bytecode checks, custom hash inversions, and any puzzle you can write as equations.

Compared to `angr`: z3 requires you to read and transcribe the check, but it is dramatically faster and never explodes. Reach for z3 first whenever you can read the logic.

## The invocations that matter

```python
#!/usr/bin/env python3
"""z3 patterns for CTF reversing."""
from z3 import (BitVec, BitVecVal, Solver, sat, unsat, Int, Bool, And, Or, Not,
                If, LShR, RotateLeft, RotateRight, Concat, Extract, Sum,
                Distinct, Optimize, simplify)

# 1. the standard flag-solving skeleton
N = 32
s = Solver()
flag = [BitVec(f"c{i}", 8) for i in range(N)]
for c in flag:
    s.add(c >= 0x20, c <= 0x7e)               # printable
s.add(flag[0] == ord("f"), flag[1] == ord("l"),
      flag[2] == ord("a"), flag[3] == ord("g"), flag[4] == ord("{"))
s.add(flag[N - 1] == ord("}"))

# 2. transcribe the binary's checks (these are examples; use the real ones)
s.add(flag[5] ^ flag[6] == 0x15)
s.add(flag[7] + flag[8] * 3 == 0x1f4)
s.add(LShR(flag[9], 2) == 0x0f)               # UNSIGNED shift right

# 3. solve and read the model
if s.check() == sat:
    m = s.model()
    print(bytes(m[c].as_long() for c in flag))
else:
    print("unsat - the transcription is wrong or the constraints conflict")

# 4. enumerate ALL solutions (to check uniqueness)
def all_models(solver, variables, limit=10):
    out = []
    while len(out) < limit and solver.check() == sat:
        m = solver.model()
        vals = [m[v].as_long() for v in variables]
        out.append(vals)
        solver.add(Or([v != val for v, val in zip(variables, vals)]))
    return out

# 5. 32-bit and 64-bit arithmetic with correct wraparound
x = BitVec("x", 32)
s2 = Solver()
s2.add(x * 0x9E3779B9 + 0x12345678 == 0xDEADBEEF)   # modular by construction

# 6. rotations and bit tricks
s2.add(RotateLeft(x, 7) ^ x == 0x1337)

# 7. array/byte extraction from a wide value
y = BitVec("y", 64)
s2.add(Extract(7, 0, y) == 0x41)              # low byte
s2.add(Concat(Extract(31, 16, y), Extract(15, 0, y)) == y & 0xffffffff)

# 8. conditionals inside constraints
s2.add(If(x > 100, x * 2, x + 5) == 210)

# 9. integers (not bitvectors) when there is no wraparound
a, b = Int("a"), Int("b")
s3 = Solver()
s3.add(a + b == 10, a * b == 21, a > 0, b > 0)

# 10. optimisation (maximise/minimise an objective)
opt = Optimize()
v = Int("v")
opt.add(v >= 0, v <= 100, v % 7 == 3)
opt.maximize(v)
if opt.check() == sat:
    print(opt.model()[v])
```

A complete, runnable example with a self-test:
```python
#!/usr/bin/env python3
"""Invert a small custom 'hash' with z3 - the shape of most keygen challenges."""
from z3 import BitVec, BitVecVal, Solver, sat, LShR

N = 16
TARGET = None


def reference(data: bytes) -> int:
    """The transformation, as read out of the binary."""
    h = 0x1505
    for b in data:
        h = ((h * 33) ^ b) & 0xFFFFFFFF
    return h


def solve(target: int, length: int) -> bytes | None:
    s = Solver()
    cs = [BitVec(f"c{i}", 32) for i in range(length)]
    for c in cs:
        s.add(c >= 0x61, c <= 0x7A)          # lowercase letters
    h = BitVecVal(0x1505, 32)
    for c in cs:
        h = (h * 33) ^ c
    s.add(h == target)
    if s.check() != sat:
        return None
    m = s.model()
    return bytes(m[c].as_long() & 0xFF for c in cs)


if __name__ == "__main__":
    TARGET = reference(b"abcdefgh")
    got = solve(TARGET, 8)
    print("target", hex(TARGET), "-> recovered", got)
    assert got is not None and reference(got) == TARGET
    print("self-test passed")
```

## Gotchas

- **`>>` on a `BitVec` is an ARITHMETIC shift** (sign-extending). For C's unsigned `>>`, use `LShR(x, n)`. This is the single most common z3 bug in CTF.
- `BitVec` arithmetic wraps automatically at the declared width, matching C. `Int` does not wrap - use `BitVec` when modelling machine code.
- Comparisons on `BitVec` are **signed** by default. For unsigned, use `ULT`, `ULE`, `UGT`, `UGE`.
- `unsat` almost always means your transcription is wrong, not that the challenge is impossible. Remove constraints one at a time until it becomes `sat` to find the bad one.
- Multiple solutions mean your constraint set is incomplete. Enumerate them (pattern 4) and check against the binary.
- z3 is bad at: large multiplications between two symbolic values, real hash functions (SHA/MD5), and anything requiring factorisation. It is excellent at: XOR, addition, shifts, table lookups, and linear systems.
- Model a table lookup as a chain of `If`s, or as a z3 `Array`, or just index a Python list with a concrete index when the index is not symbolic.
- `m[c]` returns a z3 value; use `.as_long()` to get a Python int. For a signed interpretation, `.as_signed_long()`.
- Declaring 1000 symbolic bytes when only 20 matter will slow everything down. Constrain aggressively.
- Add `s.set("timeout", 60000)` (milliseconds) so a hard instance does not hang your terminal forever.

## If it fails, use instead

| Situation | Alternative |
|---|---|
| You cannot read the check | `angr` (`ctfbrain search angr`), which explores paths for you |
| The check involves a real hash | `hashcat` with a mask, or brute force |
| Checks are byte-independent | plain brute force: 256 * len |
| Number-theoretic constraints | SageMath (`ctfbrain search sagemath`) |
| Pure SAT (boolean) problems | a SAT solver (`minisat`, `cryptominisat`, `pysat`) |
| Integer linear programming | `pulp`, `ortools` |
| Very large symbolic systems | `claripy` (angr's z3 wrapper) with simplification, or split the problem |
